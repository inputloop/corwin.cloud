# UI audit, 2026-11-01: corwin.cloud and topology against TopoForge as Bryant made it

**The question (Corwin, 2026-11-01).** "The UI/UX changes vs Bryant's last version are bad: I cannot
see a single change that makes sense to me as adding value for users."

**The baseline.** "Bryant's last version" is TopoForge 1.5 as Bryant released it (topoforge commit
3faceb2), plus his example drawing of how Gitcha works (e5b646c, 2026-10-30). TopoForge 1.6 and 1.7
were our changes inside TopoForge; they are listed too.

**The rule we applied.** Each difference gets one line: what a person using the site gains, if
anything. No nameable gain: removed or tucked away. Prefer TopoForge's own interface; what we add
should be data (drawings, pages, files) or small, optional and clearly better.

## What was observed (before this change)

Seen in Chromium at 1280 and 390 pixels, from a build of corwin.cloud with topology staged, and by
reading `build.py` (corwin.cloud) and `www/app.html` (topology):

- corwin.cloud's home page framed topology's `app.html`, which framed TopoForge: a frame in a frame.
  At 1280 pixels TopoForge got about 800 by 500 pixels; at 390 pixels it was below the fold, under
  four settings panels.
- `app.html` put a settings column (20rem) beside TopoForge and three buttons above it.

## Each difference, and what became of it

| # | Difference from TopoForge as Bryant made it | What a person gains | Done |
|---|---|---|---|
| 1 | TopoForge inside `app.html` inside corwin.cloud's page (two frames) | Nothing; it lost TopoForge its shape palette and properties at most widths | **Removed.** The home page frames TopoForge itself, full width |
| 2 | Settings column beside the drawing (`app.html`) | Only when a graph server is in use | **Tucked**: one closed "Settings" line above the drawing in topology; not on corwin.cloud's home |
| 3 | "Where the graph comes from" (API address) | Real, with a topology server; on corwin.cloud there is none, so "topology project (gw26)" fetched a missing address | **Tucked** (topology); not shown on corwin.cloud |
| 4 | "Draw the graph" and "Go" buttons | Only with a server; without one each only says it cannot | **Hidden until an address is in use** (topology); not on corwin.cloud |
| 5 | "Copy as a prompt" | Little: it listed graph nodes and left the drawing out | **Kept and made useful**: it now carries TopoForge's own story of the drawing |
| 6 | "Look" (classic, console, cards) | None inside the drawing: it restyled only the page around TopoForge | **Tucked** in topology's settings (kept so nobody is stuck with a look they chose); not on corwin.cloud |
| 7 | "Read drawings as" (notation) | None visible: it changed one sentence under the menu | **Tucked**; notations become data in the drawings (point 4 of AMBITIONS.md) |
| 8 | "Colours" and "Light or dark" | None: TopoForge has its own light/dark button | **Tucked**; on corwin.cloud TopoForge's own button is the only one |
| 9 | "less motion" | None inside the drawing | **Tucked** |
| 10 | "Private parts" (show, hide, auto) | Real with a server; on a public static site nothing private is ever sent | **Tucked** (topology). corwin.cloud applies the rule at build time with the floor "never" and says on each page what was kept back |
| 11 | "Export my settings" / "Bring back an export" | Settings of the host page only; TopoForge's own File menu keeps drawings | **Tucked** (topology) |
| 12 | Upgrade wizard (export before, Accept all, ACCEPT) | Real for topology's stored settings; never shown on corwin.cloud | **Kept** in topology; nothing to do on corwin.cloud |
| 13 | corwin.cloud's note under the drawing | Bryant's credit and the plain fact that drawings stay in the browser | **Kept**, shorter, with "the drawings as a file" and "Start again" |
| 14 | TopoForge 1.6: the Story panel (the drawing in words) | A text alternative for people who cannot see the picture; a file for any reader | **Kept** (inside TopoForge, not edited here) |
| 15 | TopoForge 1.6: keyboard and labelling fixes | Usable without a mouse; screen readers name every field | **Kept** |
| 16 | TopoForge 1.7: `?load=` for a same-origin drawing | Lets a page open a drawing in TopoForge without a second interface | **Kept**: it is how the default drawings open |
| 17 | On first visit, TopoForge's sample office network | Bryant's welcome; still one click away (Load sample network) | **Replaced on corwin.cloud only** by the shop's drawings, and only when TopoForge has kept nothing in this browser |

## What was added, and why each earns its place

| Added | What a person gains | Kind |
|---|---|---|
| The default drawings: one TopoForge page per directory project, obsmage's workflows and scenes, Bryant's Gitcha drawing | Every project, drawn, in TopoForge's own page tabs; movable, changeable, savable | Data |
| Layers named words, abstract, operational, physical, flow | Switch views with TopoForge's own Layers panel | Data |
| `index.html?drawing=<project>` (the directory's "Drawing" links) | Opens that project's page by pressing TopoForge's own tab; refuses to do it over your own drawing | Small script, optional |
| "Start again from the shop's drawings" | The way back after you changed or replaced the drawing | Small, optional |
| `/demo/` pages | Every app either running here or explained, with credit, licence and how to run it | Pages |

## How to check it

- `sh tests/run.sh` (corwin.cloud): the browser checks open the home page, count TopoForge's page
  tabs against the directory, open `?drawing=quantum3d5`, and show that a working copy of your own
  is not replaced.
- `node tests/a11y-check.mjs` and `--plant` (topology): the settings start closed, Draw and Go stay
  hidden with no address, the prompt carries the story; each has a planted fault that must be caught.
